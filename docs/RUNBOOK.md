# Runbook

## Run locally
```bash
cp .env.example .env              # add GROQ_API_KEY
docker compose up --build          # http://localhost:8000  (Phoenix: http://localhost:6006)
docker compose --profile local up  # + Ollama; then GIGBID_PROFILE=local and `ollama pull qwen3:4b` inside the container
```
Without Docker: `pip install -r requirements-eval.txt`, start Postgres (pgvector) and Redis, then
`python scripts/run_stack.py` (GigSim + MCP servers), `uvicorn apps.api.main:app`, `arq worker.main.WorkerSettings`,
`cd apps/web && npm ci && npm run dev`.

## Deployed instance (Render free tier)
* Blueprint `render.yaml`: web service (Docker, all-in-one mode) + free Postgres + free Key Value.
* Secrets set in the Render dashboard only: `GROQ_API_KEY`, `REVIEWER_EMAIL`, `REVIEWER_PASSWORD`; `GIGBID_SECRET`
  and `GIGSIM_ADMIN_KEY` are generated by Render.
* The free instance sleeps after 15 minutes without traffic; the first request then takes ~1 minute.
* GigSim's database lives on the instance's ephemeral disk and is re-seeded after a restart; on start-up the API
  re-provisions every user's GigSim account with the same key, so users keep working (old proposals/threads reset).
* Render's free Postgres expires 30 days after creation: recreate it from the blueprint if needed.

## Operations
| Situation | What GigBid does | What you do |
|---|---|---|
| GigSim/Upwork down | health shows `degraded`, UI banner; marketplace calls fail fast into `MarketplaceUnavailable`; worker retries with backoff; analysis of stored jobs continues | nothing; demo: `POST /api/demo/fault {"down": true}` |
| LLM provider 429/5xx | bounded retries with backoff, then the node's fallback model (config), then rules-only fallback for analyst/risk | check Groq limits |
| Node keeps failing | thread -> `dead_letter`, reason shown in inbox and run viewer | re-analyse from the job page |
| Thread exceeds step/token budget | thread -> `needs_attention` | inspect the run trace |
| Crash between approval and submit | thread resumes from the Postgres checkpoint at `submit`; same idempotency key -> GigSim returns the original submission | nothing |

## Live Upwork mode
Settings -> Connect Upwork (OAuth 2.1 against `https://mcp.upwork.com/mcp`, dynamic client registration + PKCE via the
MCP SDK). Tokens are encrypted per user (`common/crypto.py`). Reads run every `marketplace.live_poll_minutes` (180)
minutes. Proposals/messages are created only as Upwork drafts after approval in GigBid; the freelancer confirms them on
Upwork. Map Upwork's tool names in `mcp_servers/marketplace/adapters/upwork_tool_map.yaml`. Not exercised against a
live account in this submission (no Upwork account was available); see the report's limitations.

## Absorbing a platform policy change
See `docs/CHANGELOG.md` (2 November 2026 update): edit `data/policy_pack/rules.yaml` and `agent/config.yaml`; GigSim's
`get_policy` is read at run time for Connects pricing and disclosure requirements.
