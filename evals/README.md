# Evaluation

Every number in `README.md` and the report comes from a JSON file in `evals/results/`. Each file carries a
`provenance` block: git commit, model profile, models per node, embedder, reranker, thresholds and timestamp.
CI (`scripts/ci_guards.py`) fails if a number tagged in the README does not match its results file.

## Datasets

| file | what | labels |
|---|---|---|
| `datasets/dev_set.jsonl` | 600 synthetic jobs (200 per persona); ~45% bid, 12% scam, 10% planted injection | gold decision, graded gold evidence per requirement, fair price band, scam type, injection type |
| `datasets/gold/*_corpus_manifest.json` | which portfolio file evidences which project (evaluation side only) | - |
| `datasets/stream_labels.jsonl` | labels for the jobs GigSim releases over simulated time | - |
| hidden test | generated at run time from `HIDDEN_TEST_SEED`, written to `var/` (git-ignored), never used for tuning | - |

How they were built and their limits: `docs/DATA_CARD.md`. Market statistics come from the Kaggle Upwork job
postings dataset (ODC-By); everything about the personas and clients is synthetic.

## Runners

All runners are `python -m evals.runners.<name>`; the commands below are exactly what produced the committed files
(see `ci/mac_runner.sh` and the job scripts under `runs/queue/` on the machine that ran them).

| runner | question | output | LLM? |
|---|---|---|---|
| `rag_eval --variants nollm --embedder fastembed` | B2: which retrieval variant finds the gold evidence? Recall@5, capped Recall@5, MRR, nDCG@10, p95 latency, per persona | `rag_benchmark.json` | no |
| `rag_eval ... --embedder wordllama` | same, different embedder | `rag_benchmark_wordllama.json` | no |
| `rag_ablation` | B4: which part of V9 matters? | `rag_ablation.json` | no |
| `fit_calibration` | thresholds by measurement (tune = dev jobs 100-199/persona, check = 0-99) | `fit_calibration.json` | no |
| `decision_eval --limit 7` | end to end on the check split: bid F1, scam recall, price in band, unsupported-claim rate before/after verification, p95 latency, cost | `decision_eval.json` | yes |
| `decision_eval` (before fix) | the same run with the first matcher (kept as a record) | `decision_eval_precalibration.json` | yes |
| `multiagent_comparison --limit 4` | C: hand-built graph vs single ReAct agent vs `langgraph-supervisor`, same tools and models | `multiagent_comparison.json` | yes |
| `tool_granularity --tasks 40` | A: fine vs coarse vs rewritten tool sets: tool-selection accuracy, argument accuracy, tokens per task | `tool_granularity.json` | yes |
| `injection_eval --limit 12` | E4: attack success rate with defences off vs on | `injection_eval.json` | yes |
| `decision_eval` at commits `70c8062` / `a783067` | change request: same jobs before/after absorbing the 2026-11-02 policy | `change_request_before.json`, `change_request_after.json` | yes |
| `portfolio_builder_eval --llm` | X3: does the builder change held-out coverage; how many LLM case-study claims survive the code check | `portfolio_builder_eval.json` | partly |
| `human_eval build` / `analyse` | judge calibration (30 items labelled by me at `/label`, Cohen's kappa) and blind pairwise panel (`/panel`) | `judge_items.json`, `panel_pairs.json`, `human_eval.json` | judge only |
| `hidden_test --per-persona 6` | the decision evaluation on jobs nobody tuned on | `hidden_test.json` | yes |

## Reproduce

```bash
pip install -r requirements-eval.txt
export GROQ_API_KEY=...            # free tier is enough at these sizes
export GIGBID_PROFILE=open EMBED_THREADS=8
python -m evals.runners.rag_eval --variants nollm --embedder fastembed --out rag_benchmark.json   # ~35 min on an M4
python -m evals.runners.fit_calibration
export GIGBID_FIT_BID=$(python -c "import json;print(json.load(open('evals/results/fit_calibration.json'))['summary']['fit_bid'])")
python -m evals.runners.decision_eval --limit 7 --concurrency 2
```

Runners that need GigSim and the MCP servers start them in-process (`scripts/run_stack.py`), so no Docker is needed.

## Gates

`decision_eval --gate` (used by `.github/workflows/eval.yml` on a 10-job smoke set) fails when bid F1 drops below
0.55 or the unsupported-claim rate after verification exceeds 0.10.

## Known biases

* The dev set and the personas were generated by the same code, so the implied-skill phrasings the retriever has
  to resolve come from the same lexicon the skill graph uses. V9's lead over V0-V6 is therefore an upper bound;
  the hidden test and the per-persona breakdown are the honest checks.
* LLM runs are small (tens of jobs) because of free-tier rate limits; every table reports n.
